# Coco 设计规范

> 适用范围：AI 陪伴 App MVP，iPhone 竖屏优先  
> 产品形态：Flutter 单 App，按账号角色展示老人模式与子女模式  
> 设计关键词：老人端「温暖、从容、清楚」；子女端「现代、可信、克制」

## 1. 设计目标

Coco 的两个角色共享同一产品价值和品牌，但不强求使用同一种页面密度。

- 老人端首先解决“敢不敢点、看不看得懂、做错后能不能回来”。界面应像一位耐心、可信的陪伴者，而不是控制面板。
- 子女端首先解决“最近是否安稳、哪里需要关注、我现在能做什么”。界面应现代、高效，但不能营造实时监控或健康诊断感。
- 共享体验强调家庭连接、授权透明和真实状态，不用夸张拟人化掩盖 AI 身份。

## 2. 核心原则

### 2.1 老人端：一屏一事

每屏只有一个清晰的主要任务。最重要的操作放在拇指容易触达的位置，并配直接文字；次要能力逐级展开，不依赖隐藏手势。

### 2.2 说话优先，触控确认

语音是老人端的首选输入方式，但会产生真实后果的动作必须显示结构化草稿、语音复述并等待点击或明确语音确认。

### 2.3 温暖不等于低对比

暖色用于营造氛围和强调主操作，正文仍使用深色中性色。避免浅橙文字配米色背景、整屏泛黄或依赖红绿区分状态。

### 2.4 信息有出处

家庭留言明确显示真实发送者；提醒明确显示创建者；摘要明确展示周期、更新时间和信息范围。AI 生成内容应标识为 AI 整理，不能伪装成家人原话。

### 2.5 允许反悔

保存、共享、绑定、建议提醒、移除成员等行为都应提供取消、撤销或清晰的后续修改入口。

### 2.6 不制造监控感

子女端不显示“老人刚刚说了什么”、连续在线轨迹或未经授权的敏感信息。用低频摘要和有行动价值的事项替代密集状态流。

## 3. 品牌与视觉方向

### 3.1 品牌气质

Coco 的视觉应有生活气息，但不幼稚；亲切，但不使用儿童化卡通；可靠，但不模仿医疗系统。

可使用的视觉联想：

- 晨光、木质家具、织物、茶杯、手写便签。
- 圆润但克制的几何形。
- 轻柔呼吸、点头、声波等与交互直接相关的动效。

避免：

- 医院蓝、生命体征曲线、警报仪表盘。
- 霓虹渐变、玻璃拟态、强发光和高频粒子。
- 过度可爱的婴儿化角色。
- “24 小时守护”“实时监控”等造成承诺或压力的表达。

### 3.2 Logo 与角色

Logo 宜使用简洁圆形或对话轮廓，适合大图标识别。虚拟角色是对话状态的情感反馈载体，不应占满所有功能页，也不能用拟人动画掩盖录音、加载或失败状态。

MVP 的 3 个角色应共享相同骨架和状态语义：

- `idle`：轻微呼吸。
- `listening`：稳定注视，配清晰录音点与声波。
- `processing`：轻点头或柔和光环，不显示虚假进度。
- `speaking`：低幅口型或节奏响应。
- `error`：保持平静，停止装饰动画，突出解决办法。

## 4. 色彩系统

颜色名称表达用途，代码中应使用语义 token，不直接使用色值名称。

### 4.1 共享基础色

| Token | 建议色值 | 用途 |
|---|---:|---|
| `neutral.950` | `#26231F` | 主要正文 |
| `neutral.700` | `#5D574F` | 次要正文 |
| `neutral.500` | `#817A71` | 辅助信息 |
| `neutral.300` | `#CFC8BE` | 边框、禁用状态 |
| `neutral.100` | `#F3EFE9` | 分隔背景 |
| `white` | `#FFFFFF` | 卡片与反色文字 |
| `success` | `#397A58` | 完成、正常 |
| `warning` | `#A86113` | 待确认、需留意 |
| `danger` | `#B33A34` | 错误、删除、高风险 |
| `info` | `#326B8C` | 一般信息 |

所有语义状态必须同时配文案或图标，颜色不能作为唯一判断依据。

### 4.2 老人模式主题

| Token | 建议色值 | 用途 |
|---|---:|---|
| `elder.background` | `#FFF8ED` | 页面主背景，柔和暖米色 |
| `elder.surface` | `#FFFFFF` | 内容卡片 |
| `elder.primary` | `#C85F36` | 主按钮、选中和关键强调 |
| `elder.primaryPressed` | `#A94829` | 主按钮按下 |
| `elder.primarySoft` | `#F9DED0` | 柔和提示和选中背景 |
| `elder.secondary` | `#7C6848` | 次操作、角色辅助色 |
| `elder.focus` | `#784128` | 焦点描边 |

暖色面积以背景和关键动作形成层级，不要给所有卡片都加橙色边框。主按钮上的文字使用白色，并通过真机检查正常与大号字体下的对比度。

### 4.3 子女模式主题

| Token | 建议色值 | 用途 |
|---|---:|---|
| `family.background` | `#F6F8F7` | 页面背景 |
| `family.surface` | `#FFFFFF` | 卡片和底部导航 |
| `family.primary` | `#28786B` | 主操作、选中和链接 |
| `family.primaryPressed` | `#1F6258` | 按下状态 |
| `family.primarySoft` | `#DDEFEA` | 标签、筛选选中 |
| `family.accent` | `#D97745` | 关怀动作、品牌呼应 |
| `family.border` | `#DEE5E2` | 卡片与分隔线 |

子女端以深青绿建立现代、可信的主基调，用暖橙作为家庭关怀的少量点缀，从而与老人端保持品牌联系。

### 4.4 深色模式

MVP 若未完成独立可访问性测试，不要简单反转颜色宣称支持深色模式。可先跟随浅色品牌主题；后续增加深色模式时需重新验证角色素材、语义色和动态字体。

## 5. 字体与内容层级

优先使用 iOS 系统字体并跟随 Dynamic Type，不在正文中使用装饰字体。

### 5.1 老人模式字号

| 样式 | 建议基准 | 字重 | 行高 |
|---|---:|---|---:|
| `elder.display` | 34pt | 700 | 1.20 |
| `elder.title` | 28pt | 700 | 1.25 |
| `elder.subtitle` | 24pt | 600 | 1.30 |
| `elder.body` | 20pt | 400–500 | 1.50 |
| `elder.button` | 22pt | 700 | 1.20 |
| `elder.caption` | 18pt | 500 | 1.40 |

老人端不使用小于 18pt 的必要信息。金额、日期、提醒时间和授权范围使用清晰的完整文案，不用细小角标承载关键信息。

### 5.2 子女模式字号

| 样式 | 建议基准 | 字重 | 行高 |
|---|---:|---|---:|
| `family.display` | 30pt | 700 | 1.20 |
| `family.title` | 24pt | 700 | 1.25 |
| `family.subtitle` | 20pt | 600 | 1.30 |
| `family.body` | 16–17pt | 400 | 1.45 |
| `family.button` | 17pt | 600 | 1.20 |
| `family.caption` | 14–15pt | 400–500 | 1.35 |

### 5.3 文案风格

老人端：

- 使用口语化短句，一次表达一个意思。
- 按钮写动作结果：“和我说话”“确认这个提醒”“播放女儿的留言”。
- 避免“提交、配置、授权 scope、异常、同步失败”等系统术语。
- 不仅说“失败”，还要告诉用户能做什么以及内容是否保存。

子女端：

- 简洁直接，可使用常见移动端术语，但避免医学判断。
- 摘要写事实和趋势，不将缺少数据解释为异常。
- 待关注卡片说明来源和建议动作，例如“本周有 2 次提醒未确认，可先发条留言问问”。

## 6. 布局、间距与形状

使用 4pt 基础网格，常用间距：

| Token | 数值 | 用途 |
|---|---:|---|
| `space.1` | 4pt | 图标内部微调 |
| `space.2` | 8pt | 紧密内容 |
| `space.3` | 12pt | 标签与文字 |
| `space.4` | 16pt | 子女端常规间距 |
| `space.5` | 20pt | 老人端相关内容 |
| `space.6` | 24pt | 卡片内边距 |
| `space.8` | 32pt | 老人端区块间距 |
| `space.10` | 40pt | 大区块分隔 |

### 老人模式

- 页面水平安全边距建议 24pt，紧凑机型不低于 20pt。
- 使用单列流式布局；最大字号下让内容纵向扩展和滚动。
- 卡片圆角建议 20–24pt，内边距 24pt。
- 主按钮宽度尽量铺满内容区，高度建议 96pt，最低不小于 72pt。
- 普通点击目标最小 56×56pt；相邻点击目标间隔不小于 12pt。
- 避免并排放置三个以上操作。确认页面最多一主一辅，危险操作与主操作分离。

### 子女模式

- 页面水平边距 16–20pt。
- 卡片圆角 16–20pt，内边距 16–20pt。
- 主按钮建议高度不低于 52pt，点击目标不小于 44×44pt。
- 可使用两列小指标卡，但关键信息和可操作事项仍用单列。
- 底部导航固定三项（近况 / 留言 / 家庭），每项包含图标和文字。子女建议提醒独立页延后，提醒概况嵌在近况内。

### 阴影与描边

阴影仅用于表达层级：

- 老人卡片：低透明暖灰阴影，模糊 16–24pt，禁止强悬浮。
- 子女卡片：优先 1pt 描边或极浅阴影，保持现代克制。
- 选中、焦点和错误状态使用明确描边，不能只加阴影。

## 7. 图标、插图与数据呈现

- 使用统一的圆角线性图标家族，图标必须配文字，老人核心操作禁止仅图标。
- 老人端常用图标建议 28–32pt；子女端 22–24pt。
- 危险操作不使用可爱插图弱化后果。
- 空状态插图应简洁，并紧邻下一步操作。
- 摘要趋势优先使用“比上周多 / 少”“本周 5 次中完成 4 次”等自然语言。
- MVP 避免复杂折线图、环形图和健康评分。确需图表时必须有文字结论、明确时间范围和无数据状态。

## 8. 核心组件

### 8.1 `ElderPrimaryAction`

老人端全宽主按钮：

- 默认高度 96pt，圆角 24pt。
- 文字不小于 22pt，可配 28pt 图标。
- 支持默认、按下、加载、禁用和焦点状态。
- 加载时保留动作语义，例如“正在准备对话…”，不只显示转圈。

### 8.2 `ConversationStatusPanel`

包含角色、当前状态文案、字幕与必要声波：

- 录音状态持续显示红色录音点和“正在听您说”。
- 处理中显示“我想一想”，超过 2 秒可播放轻量等待语。
- 播放时显示逐句字幕，并提供“打断”和“再听一遍”。
- 网络或语音失败时角色停止装饰动画，显示大字解决方案。

### 8.3 `ReminderCard`

老人端卡片优先展示时间和事项，再展示来源与重复规则；操作为“完成 / 稍后提醒 / 跳过”。“跳过”是次要操作，不能紧贴“完成”造成误触。

子女端卡片可增加状态、完成趋势和建议来源，但不得让子女直接激活未经老人确认的提醒。

### 8.4 `ConsentCard`

必须回答：

- 将分享什么。
- 分享给谁。
- 用来做什么。
- 何时生效。
- 如何撤销。

开关关闭即为不共享，默认值遵循最小共享。敏感信息不使用批量“全选授权”。

### 8.5 `DigestCard`

显示周期、更新时间、AI 整理标识和信息范围。内容分为：

1. 本周概览。
2. 提醒完成情况。
3. 值得关心的事项。
4. 可以采取的关怀动作。

无足够授权数据时显示“本周可用信息较少”，不推断老人状态异常。

### 8.6 `FamilyMessageCard`

显示真实发送者、发送时间、内容与送达/播放状态。AI 转达时必须先说明“这是某某给您的留言”。

### 8.7 `StateNotice`

统一承载离线、权限关闭、局部失败和同步等待状态。使用图标、标题、说明和一个明确动作，不使用短暂 toast 承载需要老人阅读的重要信息。

## 9. 页面规范

### 9.1 E01 老人首页

从上到下：

1. 简短问候和当前角色，避免堆叠日期、天气等非核心信息。
2. 虚拟角色与状态。
3. “和我说话”主按钮，位于第一屏最明显位置。
4. 今日最近一项提醒；无提醒时显示“今天还没有提醒”。
5. 家庭留言或“联系家人”入口。
6. 文字明确的“更多”入口。

首页不使用底部四栏导航，不展示统计图、信息流或多个同权重彩色卡片。

### 9.2 E02 对话页

- 顶部仅保留可理解的返回/结束入口。
- 中部角色与大字状态持续可见。
- 字幕可滚动，但当前句始终清晰。
- 底部主操作随状态变化：“开始说话 / 说完了 / 打断 / 继续说”。
- 录音、处理、播放三种状态必须视觉互斥。
- 取消或退出时说明是否保存了内容。

### 9.3 E03 今日提醒

- 默认先显示当前待办，再显示稍后的提醒，已完成内容折叠在末尾。
- 每张卡只突出当前可执行动作。
- 无提醒时提供“用说话创建提醒”的引导。
- 离线动作要即时反馈，并说明“联网后会同步”。

### 9.4 E04 提醒确认

以大字逐项展示“做什么、什么时候、是否重复、由谁建议”。系统语音复述后，主操作为“确认这个提醒”，次操作为“修改”，取消放在更低层级。

过去时间、时区变化或规则冲突需要自然语言解释，不暴露 RRULE 等技术格式。

### 9.5 E05 家人

优先展示未播放留言，再展示家庭成员。联系动作打开系统电话或消息界面，并由老人最后确认；不可自动拨号。

### 9.6 E06 记忆与隐私

- 用“我记住的事”而不是数据库或模型术语。
- 逐条显示内容、类别、是否分享及分享对象。
- 编辑、停止分享、删除是独立动作。
- 删除前说明对未来陪伴的影响，删除后提供短时撤销。
- 健康类内容明确标记为敏感且默认不共享。

### 9.6b E06b 历史记录

功能菜单在「我的」前增加「历史记录」入口（父母端 token，大点击区）。

- 列表：按时间倒序展示每次通话，卡片为日期时间 + LLM 短标题（失败时回退预览）；有标题时可附一行预览；空态说明「只有您自己能看见」。
- 详情：顶栏用短标题（无则「这次聊天」）；时间线展示「您 / 可可」大字对话；工具调用用中性底条白话说明（如「帮你记住：…」），不展示 JSON。
- MVP 暂不提供删除、回放音频或子女侧入口。
- 仍禁止完整聊天或原始音频向子女同步。

### 9.7 子女端导航（三栏）

底部固定三栏，每项含图标与文字：

1. **近况** `/child`：今日状态结论与待办。
2. **留言** `/child/messages`：报平安列表与撰写。
3. **家庭** `/child/family`：绑定关系与账号设置。

全屏子页（盖住底栏）：加入家庭 `/child/join`、报平安撰写 `/child/messages/compose`。  
不做第四栏「提醒」：子女远程建议提醒延后；未确认提醒仅在近况内只读展示。

### 9.8 F01 子女近况首页

从上到下：

1. 简短问候（昵称）；MVP 仅一位老人时不展示切换器。
2. **状态结论区**：总体 headline；`NEED_CONTACT` 时展示原因，并提供「打开电话 App」（不预填号码、不自动拨号）。
3. **需要关注**：父母授权后的关怀摘要；空态「今天没有需要你处理的事」。
4. **提醒概况**：只读未确认/升级项，措辞仅「未收到确认」。
5. `NORMAL` 时可提供轻量次入口「给父母报个平安」；报平安主入口在留言 Tab，避免首页双入口。

不使用红色大数字制造焦虑。严重安全提醒若未来纳入，必须有明确来源、时间、置信边界和后续动作。授权关怀摘要嵌在本页，独立「周摘要」页延后。

### 9.9 F02 提醒（延后）

子女创建建议提醒不在 MVP。确认页与列表若后续加入，须显示「等待长辈确认」，不能把未响应等同于拒绝或未完成。

### 9.10 F03 家庭留言

留言 Tab 采用列表而非聊天室错觉。顶部说明用途；空态与列表上方提供「报个平安」。撰写页：预设关怀语可编辑，AI 转译预览后确认发送；展示发送时间与转达文案，不伪造已读。

### 9.11 F04 家庭与账号

家庭 Tab 展示绑定状态、授权说明（「由长辈决定」），以及账号昵称与退出登录（危险样式 + 二次确认）。未绑定引导加入家庭。MVP 不做解绑、多成员复杂权限。

## 10. 状态与反馈

每个页面和组件必须设计以下状态：

| 状态 | 设计要求 |
|---|---|
| 加载 | 使用稳定骨架或带说明的加载，不让主要布局跳动 |
| 空 | 说明为什么为空，并给出合适下一步 |
| 错误 | 通俗说明、恢复动作、数据是否保存 |
| 离线 | 保留可用能力，标明哪些动作会稍后同步 |
| 无权限 | 解释授权关系，不诱导子女绕过老人 |
| 成功 | 紧邻动作提供确认，重要写操作显示最终内容 |
| 待确认 | 使用琥珀语义与明确文字，不等同于失败 |
| 禁用 | 说明原因；必要动作不能长期无解释地灰掉 |

反馈优先级：

1. 页面内持久状态。
2. 与操作相邻的内联反馈。
3. 对话框，仅用于高后果确认。
4. 短暂提示，仅用于低风险且可忽略的信息。

## 11. 动效与声音

- 老人端状态切换建议 240–360ms，缓动柔和；子女端 160–240ms。
- 支持 Reduce Motion 时移除位移、缩放和循环动画，保留透明度或即时切换。
- 录音开始/结束、提醒完成可使用轻柔触觉或声音，但必须尊重系统设置并允许关闭。
- 不使用声音作为唯一反馈。
- AI 播放与系统通知、来电或其他音频冲突时，立即进入明确的暂停/中断状态。
- 用户点击“打断”后，视觉和音频反馈应立即发生，不等待服务端确认。

## 12. 可访问性清单

所有 P0 页面发布前必须通过：

- 最大 Dynamic Type 下核心内容不截断，主操作仍可达。
- VoiceOver 阅读顺序符合视觉顺序。
- 控件 label 描述动作，value 描述当前状态，hint 只补充必要结果。
- 录音、播放、待确认和错误状态会通过可访问性公告更新。
- 每个触控目标达到对应角色最小尺寸。
- 前景与背景对比符合 WCAG AA；大字标准不能成为降低普通正文对比的借口。
- 支持系统粗体、高对比度和 Reduce Motion。
- 只用颜色、位置、动画或声音表达的信息都有文字替代。
- 装饰角色和背景不重复朗读。
- 手指精细控制较弱时，不依赖滑动、拖拽、长按或双击完成主流程。

## 13. 响应式与极端场景

- iPhone 竖屏优先，覆盖小屏设备、安全区、灵动岛和底部 Home Indicator。
- 老人端最大字号下优先转为单列、增加页面滚动，不缩小文字或点击区。
- 键盘弹出时确保当前输入、错误提示和确认按钮可见。
- 长姓名、长提醒标题、24 小时制、不同语言和跨时区规则允许换行。
- 弱网时保留当前字幕和草稿，避免重复提交。
- 缓存摘要必须显示更新时间，避免旧数据被理解为当前状态。

## 14. 设计评审与交付要求

每个新增页面或核心变更，设计/实现评审至少检查：

1. 当前角色和唯一主任务是什么。
2. 默认、加载、空、错、离线、无权限和最大字号状态是否齐全。
3. 是否存在未经确认的保存、共享、发送或正式执行。
4. 老人是否能看懂录音、处理和播放状态。
5. 子女看到的信息是否有授权、来源与时间范围。
6. 是否可以撤销，危险操作是否清楚区分。
7. 是否使用设计 token，而非页面级任意色值和间距。
8. VoiceOver、点击区域、对比度和 Reduce Motion 是否验证。
9. 文案是否真实、简短，不包含医疗承诺、监控暗示或虚假成功。
10. 真机上是否仍保持老人端温暖从容、子女端现代克制的风格差异。

设计稿、组件故事或截图应至少包含：

- 老人端标准字号与最大字号。
- 子女端单老人和多老人状态。
- 麦克风/通知权限拒绝。
- 离线提醒操作。
- 子女建议提醒等待老人确认。
- 敏感信息二次确认与撤销共享；记忆由语音侧静默维护，父母可在记忆页查看/删除。
- 摘要数据不足和授权被撤销。

## 15. MVP 暂不设计

除非 PRD 更新，不为以下能力建立入口或视觉占位：

- 医疗诊断、药物剂量调整、急救自动化。
- 跌倒检测、生命体征和连续定位。
- 后台环境监听。
- 完整聊天或原始音频向子女同步。
- 复杂 3D 数字人、角色商城和开放角色创作。
- 安卓、iPad 专用版、网页端和智能音箱。
- 订阅、保险或医疗商业化流程。
