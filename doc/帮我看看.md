# 帮我看看（父母端识图）

父母端多模态能力：给可可一张图或让可可看手机屏幕，内容**一直留在首页**，用同一条 Realtime 语音继续追问；现有读图不够时，由语音模型调用工具再看原图。关掉照片 / 停止看手机只结束视觉任务，**不挂断语音**。

与 [`doc/需求.md`](需求.md) 的偏差：29.1 曾把「帮我看看」整体推到 V1.5。本文按当前产品规格纳入。

## 心智模型

「看照片 / 看眼前 / 看手机」不是另一套对话，只是给可可递画面。读完之后，听、想、说仍走现有 Realtime（`qwen-audio-3.0-realtime-plus`），和点「说话」是同一次陪伴。

| 工具 | 含义 | 取图 | 本期 |
| --- | --- | --- | --- |
| 说话 / 对话中 | 语音陪伴 | — | 已有 |
| 看眼前 | 眼前实物 | 系统相机 | **已落地** |
| 看手机 | 手机上的内容 | **跨 App 投屏会话 + 按需抽帧** | **已落地（App）**；Web 不可用 |
| 看照片 | 相册里的照片 | **直接系统相册**，无自定义弹层 | **已落地** |

### 看照片 / 看眼前

```text
点「看照片」或「看眼前」→ 取图 → 首页显示照片 +「可可正在看」
  → 多模态读图 → 接通/复用 Realtime → 注入读图上下文 → 可可开口讲
  → 照片保持在画面上，可继续追问；不够细时自动再看原图
  → 点「关闭」或说关掉照片：收起照片，语音继续
```

- **没有**单独的「换一张」按钮；要换图就再点一次「看照片 / 看眼前」。
- 「看照片 / 看眼前」是一次性动作，只短暂按压反馈，**不保持高亮**。
- 未通话时选图成功会**自动接通**语音，不必再点「说话」。
- 关掉照片 ≠ 结束说话。

### 看手机（投屏会话）

跨 App **投屏会话**：系统级屏幕共享开启后，老人可切到短信 / 微信 / 其它 App；语音不中断。给模型的是 **按触发抽的 JPEG 帧**（不是持续视频流），复用同一条识图 + Realtime 链路。

锚点场景：

- **防诈**：收到短信，想让可可看看靠不靠谱。
- **操作指导**：某个 App 不会操作，打开卡住的页面问下一步点哪里。

```text
点「看手机」→ 确认说明卡 → 系统投屏授权
  → 接通/复用 Realtime →「我开始看手机了，打开要看的页面后跟我说」
  → 切到目标 App
  →（安卓）画面离开可可并稳定后自动首看；或用户提问 / 说「好了」→ 抓当前帧 → 识图 → 语音回答
  → 可继续追问 / 换一屏再问（安卓后台换屏可自动再看）；点「停止看手机」或说关掉 → 停投屏，语音继续
```

- 投屏中「看手机」工具**保持高亮**。
- 投屏刚成功不急着识图（多为可可自己的界面）；等离开 App（安卓自动）或用户开口再抽帧。
- **划到后台仍可继续对话**：显式会话不因进后台停麦；Android 有语音前台服务 + 可选悬浮「可可在看屏」；iOS 依赖系统录屏红条与本地通知提示。
- 权限失败时降级：引导截屏后用「看照片」。
- Web 不支持看手机。

原则：**语音指挥，少回 App**；回可可主要为授权 / 停止 / 看大字状态。

## 范围

| 阶段 | 内容 |
| --- | --- |
| 本期 | 看照片 / 看眼前；看手机投屏会话（App 抽帧识图）；追问重识图；关图/停投屏不断线；**安卓自动首看与换屏再看、看屏存在感（无前台直播预览）** |
| 后续 | 自然语言进投屏、本地敏感遮挡闸门、iOS Share Extension；iOS 自动首看/换屏再看 |
| 明确不做 | 持续视频直送模型、多图历史、客户端关键词触发 follow-up、独立 ASR→TTS 追问路径 |

边界说明：MVP 的「看手机」是投屏会话 + 抽帧，**不是**逐帧视频流；与 Agent 总设「直播屏幕」在体验上对齐，实现上按需取帧以控成本与隐私。

**安卓本期行为（相对上方主流程的增强）**：

- 投屏成功后通知重要性提高，文案随「等待 / 正在看」更新；划到后台悬浮球显示「可可在看屏」/「正在看…」。
- **离开可可且画面稳定后自动首看**（无需先开口）；同一次投屏内换屏停住后防抖再看。
- 仍在可可前台：中间区用说明占位，或展示**已识图的外屏静态缩略图**；**禁止**用实时投屏帧做直播预览（避免镜子套娃）。
- 仍在可可前台开口：不识图，口语引导先去打开目标页（避免描述可可自己界面）。
- 抽帧带时间戳，过旧则短暂重试。

iOS 仍以用户开口抽帧为主；系统广播引导不变。

## 目标流程与状态

### 看照片 / 看眼前

`普通对话 → 取图 → 初次分析 → 看图对话 → 重新分析（按需） → 换图或关闭`

| 状态 | 页面与行为 |
| --- | --- |
| 普通对话 | 不显示照片；底部「对话中」高亮 |
| 取图 | 打开相册或相机；成功后进入初次分析 |
| 初次分析 | 显示照片；状态为「可可正在看」，右侧「关闭」 |
| 看图对话 | 照片持续显示；状态为「可以问可可｜关闭」 |
| 重新分析 | 原照片持续显示；状态为「我再仔细看一下｜关闭」 |

### 看手机投屏

```text
idle → confirming → awaitingPermission → starting
  → sharingIdle → analyzing ⇄ viewing / reAnalyzing
  → blocked | idle（停止后）
```

| 状态 | 页面与行为 |
| --- | --- |
| confirming | 说明卡：让可可看看你的手机 |
| awaitingPermission / starting | 「按提示打开看手机权限」 |
| sharingIdle | 「去打开要看的页面，然后问我」；可无帧占位 |
| analyzing / reAnalyzing | 「可可正在看」/「我再仔细看一下」 |
| viewing | 「可以问可可｜停止看手机」+ 最近一帧 |
| blocked | 「已停止看屏幕」+ 原因；投屏已停 |
| 权限拒绝 | 引导截屏 +「看照片」 |

实现文案以本文为准。截图里的「正在看这张照片」不要用。

## 技术链路

```text
取图 / 抽帧 → POST /v1/vision/look（qwen3.7-plus）→ scene_description + conversation_id
  → WS /v1/voice/realtime
  → 客户端 vision.inject（携带 look_conversation_id，source=camera|album|screenshot|screen）
  → 桥接绑定 VisionSessionState
  → session.update（照片块写入 instructions，换图/新帧整块替换）
  → response.create → 可可口语播报

追问（证据不足时）：
  Realtime 调用工具 re_vision_image(question)
  → VisionService.re_analyze（原图缓存 + 当前问题，每问最多一次）
  → 合并 scene_description → 更新 instructions
  → 可可按新证据口头回答

看手机新帧：
  同一次投屏会话内更新 look_image_cache 并 vision.inject 整块替换
```

- 识图仍用多模态 `COCO_VISION_MODEL`（默认 `qwen3.7-plus`）。
- Realtime **不看原图**，只消费读图文本；需要细节时由服务端工具再调视觉模型。
- 主路径**不再**由客户端调用 `POST /v1/vision/follow-up`。`follow-up` 接口可保留作调试，首页不接。
- LOOK `conversation_id` 是 visual session 锚点，与 Realtime 语音会话分开；原图只在进程内存缓存（TTL 约 15 分钟，单实例）。

### 原生取屏

| 平台 | 方式 |
| --- | --- |
| iOS | ReplayKit Broadcast Upload Extension + App Group 传 JPEG |
| Android | MediaProjection + mediaProjection 前台服务 |
| Web | 不支持 |

### 「字」与看图

「字」开关状态在同一通会话内保留，看图只改变文字展示范围：

| 看图状态 | 「字」 | 页面展示 |
| --- | --- | --- |
| 未看图 | 关 | 可可形象与普通语音状态 |
| 未看图 | 开 | 当前 Session 的完整对话 |
| 正在看图 | 关 | 当前照片 + 状态栏 |
| 正在看图 | 开 | 当前照片 + 当前一轮对话（叠在照片底部，卡内滚动） |

「当前一轮」指最近一条老人输入，以及可可正在说或刚说完的话；进入下一轮后替换，不在照片旁堆积全文。

- 看图且「字」已开时点「关闭」：保持「字」为开，恢复完整对话并滚到最新。
- 看图且「字」关闭时点「关闭」：回到普通可可语音界面。
- 原本「字」已开时进入看图：由完整对话改为「照片 + 当前一轮」。
- 切换过程不重复消息，不中断语音播放、倾听或对话上下文。
- 「字」只控制文字显示，不重置照片或视觉上下文。

### 关闭、换图、竞态

- 点状态栏右侧浅橙「关闭」，或语音说关掉照片：隐藏照片、清理本地图和视觉状态，语音继续。
- 投屏中点「停止看手机」或说「不用看了」：停系统投屏 + 清视觉会话，语音继续。
- 换图成功：替换旧图并开始新会话；取消选择：保留旧图和原会话。
- 开看手机时若正在看照片/看眼前，先关视觉再开投屏；CAMERA 与 SCREEN 不同时开。
- 关闭或换图后，拒绝展示或播报旧会话的迟到结果。
- 分析中继续说话：保留老人问题，分析完成后一并回答。
- 初次或重新识图失败：不自动关图/不停投屏，不猜测；允许换图、重拍或关闭。

## 追问路由（Realtime 工具）

每个问题由语音模型选择一种动作：

1. 已有视觉证据足够：直接回答。
2. 需要新的图片细节：调用 `re_vision_image`。
3. 投屏中用户说「又变了 / 好了 / 你看」：客户端先抽新帧再 inject；或工具重看缓存帧。**安卓**还可在离开可可后自动首看、换屏停住后自动再看。
4. 一般知识：无需再看图，直接回答。
5. 指代不清：简短追问一次。
6. 涉及金融操作、验证码、密码或医疗决策：停止分析并说明边界；投屏场景应 `stop_screen_share` / 客户端停投屏。
7. **安卓**仍在可可前台开口：不抽帧识图，口语引导先打开目标页。

重新识图：

- 自动触发，不要求老人确认。
- 每个问题最多重新识图一次；仍看不清则如实说明，建议拍近一点或再说一次。
- 视觉模型只输出事实和不确定处，最终回答由语音模型生成。
- 新证据只追加到当前图片的临时观察；关闭或换图后全部失效。

### 看手机回答风格

- 短信防诈：先结论（可疑 / 像正常通知 / 看不清）→ 一句话原因 → 建议（不点链接、不回验证码、可让子女看）。
- 操作指导：一次只说**一步**，等老人反馈再看下一屏。
- 支付、转账、验证码、密码、银行卡、身份凭证页：停止看屏并建议找子女。

## 接口

```text
POST /v1/vision/look          multipart: image + question? + source?
  → { confidence, headline, detail, safety_note, scene_description, conversation_id?, should_stop_screen? }

WS /v1/voice/realtime
  上行 vision.inject: { scene_description, source?, look_conversation_id }
  上行 vision.discard
  下行 vision.injected
  下行 vision.state: { phase: viewing | reanalyzing }
  下行 vision.closed
  下行 vision.stop_screen（建议客户端停投屏）
```

相册首轮默认问题：`请帮我看看这张照片里有什么。`  
看眼前：`请帮我看看这是什么、上面写了什么。`  
看手机：`请帮我看看屏幕上的内容在说什么，有没有需要小心的地方。`

Realtime 工具：

- `re_vision_image`：`question` 为老人原话；服务端按 LOOK `conversation_id` 取缓存原图再看。
- `close_vision_image`：清视觉会话并通知客户端关图。
- `stop_screen_share`：建议停止投屏（敏感页 / 用户说不用看了）；客户端执行后 `vision.discard`。

## 不可破坏的规则

- **图片不落库、不落盘**：只在内存中转发给识图模型；`conversation_items` 只写文本。
- **识图内容不写记忆**：药盒、账单、验证码等一次性信息；注入提示显式禁止对此类内容记入长期记忆。
- **不做医疗判断**：可读出药盒文字，不得解释疗效或建议剂量。
- **不承诺安全性**：不得把未知链接判定为绝对安全。
- **不做金融操作指导**：检测到支付、验证码、密码或身份凭证时停止继续分析并停止投屏。

| 能力 | 本期做法 |
| --- | --- |
