# Coco 架构约定

> 目标：结构简单、边界清晰、后续功能可直接往里加。  
> `back/` 只读参考，新代码不要照搬。

## 1. 仓库目录

```text
coco/
  backend/          FastAPI 后端
  frontend/         Flutter 客户端（首发 iOS）
  doc/              产品与设计文档
  AGENTS.md         AI / 协作者约束
  README.md         启动说明
  back/             旧实现（只读，勿改）
```

## 2. 技术栈

| 层 | 选型 |
|---|---|
| 客户端 | Flutter / Dart，Riverpod，go_router，Dio |
| 后端 | FastAPI，SQLAlchemy 2 async，Alembic，uv |
| 数据库 | PostgreSQL，独立 schema `coco` |
| 鉴权 | 手机号验证码；JWT access + opaque refresh |
| AI / 语音 | 后续接入阿里云百炼（本期不做） |

## 3. 后端分层

只有两层：

```text
modules/<feature>/
  router.py     HTTP、校验、依赖注入
  service.py    业务逻辑，直接用 AsyncSession
  schemas.py    请求 / 响应 DTO
```

约束：

- router 不写 SQL，不直接操作 ORM。
- service 不依赖 FastAPI Request / Response。
- 不做 domain / application / api 三层来回转 DTO。
- 不做全局手写 DI 容器；需要时用 FastAPI `Depends`。

公共横切放在 `src/coco/`：

```text
main.py config.py database.py logging.py errors.py security.py deps.py
models/          ORM 模型
modules/         按功能拆分的路由与服务
```

## 4. 前端分层

按 feature 组织，页面直接 watch 对应 controller：

```text
lib/
  app/                 MaterialApp、router
  core/                theme、network、storage、通用组件
  features/<name>/
    data/              API、Repository 实现
    domain/            模型
    application/       Riverpod Notifier
    presentation/      页面与局部组件
```

约束：

- 不要上帝 Repository（一个类实现全部接口）。
- 不要 AppView / AppActions 双层门面。
- 路由尽量少；登录多步骤用页面内 step，不拆成多条路由。
- 页面不写裸色值，统一走 design token。

## 5. 数据库：schema `coco`

所有新表落在 `coco` schema，与旧 `public` 表隔离。

### 5.1 本期表

| 表 | 用途 |
|---|---|
| `users` | 用户；手机号只存 HMAC；角色 `parent` / `child` |
| `phone_codes` | 验证码挑战；存 code_hash，消费后作废 |
| `auth_sessions` | refresh session；只存 token hash，刷新时轮换 |
| `families` / `family_invites` | 家庭绑定与邀请码 |
| `reminders` / `reminder_occurrences` | 日常提醒与触发确认 |
| `memories` | 长期记忆（语音侧自动写入；父母可查看删除） |
| `care_shares` | 父母授权分享给子女的摘要 |
| `family_messages` | 子女报平安 / 关怀留言 |
| `notifications` | 站内通知 |
| `conversations` | 父母端语音会话（一次实时通话一条） |
| `conversation_items` | 会话内最终转写与工具调用（父母私有，不存音频） |

### 5.2 对话历史约定

- 语音桥接在 `user.final` / `assistant.final` 与工具执行后落库。
- 通话结束时用服务端文本模型根据转写摘录生成短标题写入 `conversations.title`；无 Key 或失败时用预览文案兜底。
- 仅父母本人可读；无子女同步 API；不存原始 PCM。
- 字段与枚举以 `doc/需求.md` 为准。

## 6. 鉴权约定

- 手机号规范化为 `+86xxxxxxxxxxx`。
- 手机号与验证码只存 HMAC-SHA256（pepper）。
- access token：JWT HS256，短过期。
- refresh token：随机串，只返回一次，DB 存 hash；刷新时轮换。
- 错误响应：`{"error":{"code":"...","message":"中文可展示文案"}}`。

## 7. 角色

| 值 | 含义 |
|---|---|
| `parent` | 父母 / 老年用户 |
| `child` | 成年子女 |

JWT `role` 与 `users.role` 一致，表示当前 UI 角色；家庭权限后续由 membership 表单独判断。

## 8. 开发原则

1. 先做最小可运行闭环，再加功能。
2. 关键业务规则、权限边界写中文注释。
3. 不在仓库、日志、测试里写入真实手机号、验证码、密钥。
4. staging / production 禁止开发固定验证码与 fake 短信。
